这是一篇安装记录，不是官方教程。我的环境比较特殊：**MacBook Pro M2**，用 **VMware Fusion** 跑 **Windows 11 ARM**，再通过学校的 **AppsAnywhere** 启动 **NI Multisim 14.3**。AppsAnywhere 里 Multisim 的状态显示为 `Running`，但真正打开主程序时直接报错：

<figure>
  <img src={withBase("/notes/multisim-arm-issue/multisim-error.png")} alt="AppsAnywhere 中 Multisim 显示 Running，但启动时报 0xc000007b" />
  <figcaption>AppsAnywhere 显示服务正在运行，但 Multisim 主程序没有启动成功。</figcaption>
</figure>

## 我的判断

我一开始怀疑过许可证，但这个现象更像 **Windows ARM 兼容性问题**。Apple Silicon 上的 VMware Fusion 跑的是 ARM 版 Windows，而 Multisim 14.3 是传统 Windows 桌面软件。它可以被安装，不代表所有依赖都能在 ARM 转译层里正常加载。`0xc000007b` 本身也常见于 32/64 位库、运行库或 DLL 加载不匹配。

所以我后面没有继续把时间全部花在 AppsAnywhere 上，而是把问题拆成两件事：

<ul class="check-list">
  <li>先确认有没有能交作业的替代环境：学校 Windows 电脑、远程 lab、同学或自己的 Intel/AMD Windows 电脑。</li>
  <li>再尝试能不能在这台 ARM 虚拟机里找到一个临时可用的安装方式。</li>
</ul>

## 试过的路

低成本的修复包括安装 VC++ 2015-2022 运行库、检查 .NET、用 NI Package Manager 做 repair、重启虚拟机。这些步骤值得试，但在我这里没有解决 AppsAnywhere 版的启动错误。

真正有变化的是手动安装。我绕过 AppsAnywhere，直接从 NI 官网下载 **Multisim 14.3 Education** 安装程序。安装时我没有全选组件，而是取消了 `Offline Help` 和一个额外的 `.NET` 相关模块。这样装完以后，同一台 Windows 11 ARM 虚拟机里 Multisim 能打开：

<figure>
  <img src={withBase("/notes/multisim-arm-issue/success-to-run.png")} alt="Multisim 在 Windows 11 ARM 虚拟机中成功打开" />
  <figcaption>手动安装后的 Multisim 可以进入主界面。右侧系统信息能看到这是 ARM-based processor。</figcaption>
</figure>

授权状态可以在 **NI License Manager** 里看：

<figure>
  <img src={withBase("/notes/multisim-arm-issue/license-manager.png")} alt="NI License Manager 中 Multisim 14.3 和 Ultiboard 14.3 显示 Licensed" />
  <figcaption>License Manager 里显示 Multisim 14.3 / Ultiboard 14.3 目前可用。</figcaption>
</figure>

这里我会谨慎看待 `Licensed` 这个状态：它说明软件当前能用，但不等于学校一定给了永久密钥。NI 官网 Education 版本身有试用期，所以后续仍要确认 trial、license server 或学校授权到底是哪一种。

我发邮件问过学校 IT 能不能提供 Multisim 序列号。**ITS Client Care** 的回复要点是：

> ITS does not provide Multisim license keys.
>
> According to your BYOD Program Requirements, Macs are not permitted. I would recommend you reach out to the program coordinator for the exact reason. (You are level 1 out of 6, there could be more Windows base application in the upper levels). https://www.algonquincollege.com/byod/programs/#e
>
> You can visit us in person at Student Central and we can provide you our "Best Effort" to attempt to repair AppsAnywhere. We will most likely uninstall it from your Windows VM and double check the configuration settings during installation.

这封回复把边界说清楚了：IT 不提供 Multisim license key；BYOD 要求里 Mac 不被允许；如果还想修 AppsAnywhere，可以去 Student Central 让他们做 best-effort 检查，但这不等于 ARM 虚拟机一定能跑。

## 我会怎么处理

如果只是画基础电路，**Multisim Live**、Falstad / CircuitJS 这类网页版工具可以先顶上。但如果课程要求提交 `.ms14` 文件，还是要准备真正的 Windows 环境。

我的当前方案是：

<ol class="check-list">
  <li>短期用手动安装版完成能完成的 lab，同时注意试用期。</li>
  <li>遇到必须稳定提交的作业时，优先用学校 Windows 电脑或其他 Intel/AMD Windows 电脑。</li>
  <li>如果 AppsAnywhere 仍必须使用，就去 Student Central 做一次现场检查。</li>
  <li>以后买设备或准备高年级课程时，把 Windows-only 软件当作真实限制，不再只看“Mac 能不能虚拟化 Windows”。</li>
</ol>

这次 Multisim 确实在 Mac M2 上打开了，但这套办法比较脆弱。我不会把它当作课程作业的唯一环境。对课程来说，能按时提交比把虚拟机调到完美更重要。

  <img src={withBase("/notes/multisim-arm-issue/multisim-error.png")} alt="AppsAnywhere showing Multisim running while the app fails with 0xc000007b" />

## My read of the error

At first I wondered if this was licensing. The behavior looked more like a **Windows ARM compatibility issue**. VMware Fusion on Apple Silicon runs the ARM build of Windows, while Multisim 14.3 is an older Windows desktop application. It can install, but that does not mean all of its dependencies load cleanly through the ARM translation layer. The `0xc000007b` error often points toward runtime, DLL, or 32/64-bit library mismatches.

I stopped treating AppsAnywhere as the only path and split the problem into two parts:

<ul class="check-list">
  <li>Find a reliable way to finish course work: school Windows PCs, a remote lab, or an Intel/AMD Windows machine.</li>
  <li>See whether this ARM VM could still be made useful as a temporary setup.</li>
</ul>

## What changed

I tried the low-cost repairs first: VC++ 2015-2022 runtimes, .NET checks, NI Package Manager repair, and a VM restart. Those did not fix the AppsAnywhere launch error.

The useful change was a manual install. I bypassed the AppsAnywhere bundle and downloaded **Multisim 14.3 Education** directly from NI. During installation, I did not select every optional component. I unchecked `Offline Help` and an extra `.NET`-related module. After that, Multisim opened on the same Windows 11 ARM VM:

<figure>
  <img src={withBase("/notes/multisim-arm-issue/success-to-run.png")} alt="Multisim opened successfully inside a Windows 11 ARM VM" />
  <figcaption>Manual install result: Multisim opened. The Windows system panel also shows an ARM-based processor.</figcaption>
</figure>

The current license state is visible in **NI License Manager**:

<figure>
  <img src={withBase("/notes/multisim-arm-issue/license-manager.png")} alt="NI License Manager showing Multisim 14.3 and Ultiboard 14.3 as licensed" />
  <figcaption>License Manager showed Multisim 14.3 / Ultiboard 14.3 as currently usable.</figcaption>
</figure>

I would be careful with the word `Licensed` here. It means the software is usable at the moment; it does not prove that the college has provided a permanent key. The NI Education download can also involve a trial period, so licensing still needs to be checked separately.

I emailed school IT asking whether they could provide a Multisim serial number. **ITS Client Care** replied:

> ITS does not provide Multisim license keys.
>
> According to your BYOD Program Requirements, Macs are not permitted. I would recommend you reach out to the program coordinator for the exact reason. (You are level 1 out of 6, there could be more Windows base application in the upper levels). https://www.algonquincollege.com/byod/programs/#e
>
> You can visit us in person at Student Central and we can provide you our "Best Effort" to attempt to repair AppsAnywhere. We will most likely uninstall it from your Windows VM and double check the configuration settings during installation.

That reply sets the boundary: IT does not provide Multisim license keys; the BYOD requirement does not allow Macs; and Student Central can only offer best-effort AppsAnywhere repair. That may still be worth doing, but it is not a guarantee that this ARM VM becomes a fully supported setup.

## My practical plan

For basic circuit work, **Multisim Live**, Falstad, or CircuitJS can be enough. For assignments that require `.ms14` files, I would not rely on the Mac VM as the only option.

My plan from here:

<ol class="check-list">
  <li>Use the manual install for short-term lab work while the license state is valid.</li>
  <li>Use a school Windows machine or another Intel/AMD Windows computer for anything that must be submitted reliably.</li>
  <li>Visit Student Central if AppsAnywhere is required for a later course task.</li>
  <li>Treat Windows-only software as a real program requirement when planning future devices or setups.</li>
</ol>

In this case, Multisim did open on a Mac M2, but only through a fragile workaround. I would not use this as the only setup for course work.
