在阿尔冈昆学院的 BYOD 计划下，学生需要在自己的电脑上运行 NI Multisim 进行课程实验。我使用的是一台 **MacBook Pro M2**，通过 **VMware Fusion** 运行 **Windows 11 ARM** 虚拟机。当我从学校提供的 **AppsAnywhere** 平台安装并启动 Multisim 14.3 时，软件的后台服务虽然显示运行中，但主程序启动时弹出 **0xc000007b** 错误，无法进入界面：

<img src={withBase("/notes/multisim-arm-issue/multisim-error.png")} alt="Multisim 启动错误 0xc000007b" />

## 错误分析：架构不兼容

这个错误并非许可证问题，而是 **架构兼容性问题**。苹果自研芯片上的 VMware Fusion 只能运行 ARM 架构的 Windows 虚拟机，而 Multisim 14.3 是传统 x86/x64 Windows 桌面应用，它依赖的 DLL 在 ARM 版 Windows 下需要转译，往往会因为缺少或无法加载 32/64 位库而崩溃。VMware 官方也说明 Apple Silicon 上只能运行 ARM guest OS，而 NI 目前提供的 Multisim 安装包只有 Windows x86/x64 版本。

## 常见尝试及建议

我在尝试解决过程中整理了几条建议：

- **不要在 VMware Fusion 里反复折腾** —— 服务显示 “Running” 不代表主程序兼容，ARM 转译常常会导致报错。
- **优先使用学校的 Windows 电脑/远程实验室** —— Multisim 在传统 Intel/AMD 版 Windows 10/11 上最稳定。
- **尝试 Parallels Desktop** —— Parallels 对 Windows 11 ARM 的 x86 应用兼容性通常比 VMware 好一些，但仍不能保证 Multisim 正常运行。
- **安装必要运行库** —— 尝试安装 VC++ 2015–2022 运行库（x86/64）、.NET 3.5/4.x、运行 NI Package Manager 的 Repair 和安装 Circuit Design Suite 14.3 补丁；这些都是低成本操作，但如果依旧报错，那基本就是 ARM 转译的限制。
- **使用 Multisim Live** —— NI 提供的浏览器版在线电路仿真工具，适合基础实验，不需要安装软件；如果课程不强制提交 `.ms14` 文件，这是最快捷的替代方案。
- **了解 BYOD 政策** —— 阿尔冈昆学院的 BYOD 页面实际上不建议使用 Mac：有些课程在高年级会依赖 Windows-only 应用。如果你的专业必须使用 Windows 软件，官方建议使用 Windows 电脑。

## 手动安装的折中方案

由于我的课程需要提交 Multisim 桌面版的实验文件，我尝试绕过 AppsAnywhere 的预安装包，直接从 NI 官网下载 **Multisim 14.3 Education** 安装程序。这一版本在安装过程中提供了可选组件。我在安装时取消勾选了 `Offline Help` 以及另外一个额外的 `.NET` 相关模块，避免了安装过多的依赖。安装完成后，在同样的 Windows 11 ARM 虚拟机里竟然可以正常启动：

<img src={withBase("/notes/multisim-arm-issue/success-to-run.png")} alt="Multisim 在 Windows ARM 虚拟机中成功运行" />

通过 **NI License Manager** 可以查看授权状态：

<img src={withBase("/notes/multisim-arm-issue/license-manager.png")} alt="License Manager 显示已经授权" />

左侧 Multisim 14.3 和 Ultiboard 14.3 旁边显示绿色圆点并标注 “Licensed”，右侧 “Schematic capture and simulation” 也为绿色，这意味着软件已经处于被授权的状态，而不是试用或未激活。如果仍然是试用版，License Manager 会显示 “Evaluation” 或 “Trial”。

需要说明的是，从 NI 官网下载的 Education 版默认是 **45 天免费试用**。我发邮件问过学校 IT 能否提供 Multisim 序列号，以下是 **ITS Client Care** 的回复要点：

> ITS does not provide Multisim license keys.
>
> According to your BYOD Program Requirements, Macs are not permitted. I would recommend you reach out to the program coordinator for the exact reason. (You are level 1 out of 6, there could be more Windows base application in the upper levels). https://www.algonquincollege.com/byod/programs/#e
>
> You can visit us in person at Student Central and we can provide you our "Best Effort" to attempt to repair AppsAnywhere. We will most likely uninstall it from your Windows VM and double check the configuration settings during installation.

归纳一下：**向 IT 申请许可证密钥这条路走不通**；BYOD 政策层面 Mac 不被允许；高年级课程可能还有更多 Windows 专用软件；如果仍想用 AppsAnywhere，可以去 Student Central 当面求助，IT 会尽力重装并检查安装配置，但不保证能修好 ARM 虚拟机上的兼容问题。试用期满后就只能换其他方案。

## 总结与建议

- **Mac 上没有官方 Multisim、Linux 版也没有**，只有 Windows 桌面版。所以在 Apple Silicon 上使用 Multisim 时一定要考虑兼容性。
- 如果只是完成基础实验，可以直接使用 **Multisim Live** 或 **Falstad/CircuitJS** 这类免费的在线仿真工具；它们不需要安装，可在浏览器运行。
- 如果必须提交 `.ms14` 文件，而又只能用 Mac，那么可以尝试：
  1. **手动安装** NI 官网版 Multisim，取消可选组件，使其在 Windows ARM 上凑合运行（注意 45 天试用限制）；
  2. **使用学校 Windows 电脑或实验室**；
  3. **自备 Intel/AMD Windows 电脑** 完成实验；
  4. **去 Student Central** 请 IT 尝试重装 AppsAnywhere（Best Effort，不保证成功）。
- 最终，这个折中方案虽然让 Multisim 在我的 Windows 11 ARM 虚拟机上跑起来了，但不保证所有功能都稳定，且 BYOD 政策仍倾向于使用 Windows 电脑。因此，若有条件，还是建议在原生 Windows 环境中使用 Multisim。

本帖记录了在 Mac M2 上安装 Multisim 的过程，作为个人学习笔记留存。如果以后有新的兼容信息，我会继续更新这篇记录。

Under Algonquin College’s BYOD program, students need NI Multisim on their own machines for lab work. I use a **MacBook Pro M2** with **VMware Fusion** running **Windows 11 ARM**. After installing Multisim 14.3 from **AppsAnywhere**, background services showed as running, but the main app failed on launch with **0xc000007b** and never opened the UI:

<img src={withBase("/notes/multisim-arm-issue/multisim-error.png")} alt="Multisim launch error 0xc000007b" />

## Root cause: architecture mismatch

This was not a license issue. It was an **architecture compatibility** problem. VMware Fusion on Apple Silicon only runs ARM Windows guests, while Multisim 14.3 is a traditional x86/x64 Windows desktop app. Its DLLs are translated on ARM Windows and often fail when 32/64-bit libraries cannot load. VMware documents ARM-only guests on Apple Silicon, and NI still ships Multisim only for Windows x86/x64.

## What to try (and what to expect)

- **Do not keep reinstalling inside VMware Fusion** — “Running” services do not mean the UI is compatible; ARM translation often still crashes.
- **Prefer school Windows PCs or remote labs** — Multisim is most stable on Intel/AMD Windows 10/11.
- **Parallels Desktop** — Often handles x86 apps on Windows 11 ARM better than VMware, but Multisim is still not guaranteed.
- **Install runtimes** — VC++ 2015–2022 (x86/x64), .NET 3.5/4.x, NI Package Manager Repair, and Circuit Design Suite 14.3 patches are low-cost steps; if errors persist, you are likely hitting ARM translation limits.
- **Multisim Live** — NI’s browser simulator works for basic labs and needs no install; if the course does not require `.ms14` files, it is the fastest workaround.
- **Read BYOD policy** — Algonquin’s BYOD guidance discourages Macs for some programs because later terms rely on Windows-only tools. Official advice is to use a Windows PC when the program requires it.

## Workaround: manual NI install

My course requires desktop Multisim files, so I bypassed the AppsAnywhere bundle and downloaded **Multisim 14.3 Education** from NI. The installer exposes optional components. I unchecked `Offline Help` and an extra `.NET` module to reduce dependencies. On the same Windows 11 ARM VM, Multisim then launched:

<img src={withBase("/notes/multisim-arm-issue/success-to-run.png")} alt="Multisim running successfully in the Windows ARM VM" />

License status appears in **NI License Manager**:

<img src={withBase("/notes/multisim-arm-issue/license-manager.png")} alt="License Manager showing licensed products" />

Green dots beside Multisim 14.3 and Ultiboard 14.3 with “Licensed”, plus green “Schematic capture and simulation”, indicate activation rather than trial mode (“Evaluation” / “Trial” would show otherwise).

The Education download is a **45-day trial** by default. I emailed school IT asking for a Multisim license key. Here is the reply from **ITS Client Care**:

> ITS does not provide Multisim license keys.
>
> According to your BYOD Program Requirements, Macs are not permitted. I would recommend you reach out to the program coordinator for the exact reason. (You are level 1 out of 6, there could be more Windows base application in the upper levels). https://www.algonquincollege.com/byod/programs/#e
>
> You can visit us in person at Student Central and we can provide you our "Best Effort" to attempt to repair AppsAnywhere. We will most likely uninstall it from your Windows VM and double check the configuration settings during installation.

In short: **asking IT for a license key is not an option**; BYOD policy does not permit Macs; upper-level terms may add more Windows-only software; if you still want AppsAnywhere, visit Student Central in person and IT will try a “Best Effort” reinstall and config check — but that does not guarantee a fix on an ARM VM. Plan for what happens after the trial ends.

## Summary

- **No official Multisim for Mac or Linux** — only Windows desktop builds. Plan for compatibility on Apple Silicon.
- For basic labs, **Multisim Live**, **Falstad**, or **CircuitJS** avoid installs entirely.
- If you must submit `.ms14` files on a Mac:
  1. **Manual NI install** with fewer optional components on Windows ARM (45-day trial applies);
  2. **Use school Windows PCs or labs**;
  3. **Use your own Intel/AMD Windows PC** when possible;
  4. **Visit Student Central** and ask IT to reinstall AppsAnywhere (Best Effort, not guaranteed).
- My workaround runs on Windows 11 ARM but is not guaranteed stable, and BYOD policy still favors native Windows. Use a real Windows environment when you can.

This note documents what I tried on Mac M2, kept here as a personal lab log. I will update this page if I find newer compatibility information.
